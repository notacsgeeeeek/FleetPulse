# FleetPulse anomaly event labels

`anomaly_event_template.csv` is for authorized, de-identified event records. Use one row per confirmed event and keep the source/evidence reference separate from the model's alert. Recommended `label` values:

- `confirmed_sensor_fault`
- `confirmed_engine_abnormality`
- `no_fault_found`
- `unknown`
- `injected_sensor_anomaly` (simulation only)

Use `source_type=maintenance_confirmed` only when an authorized maintenance finding supports the label. Record the event's telemetry cycle range, affected sensor when known, finding, work performed, and post-work observation. Do not infer a fault from a FleetPulse alert alone; preserve `unknown` where evidence is incomplete. Never place names, registration numbers, or other identifying operational data in the demo folder.

`synthetic_fault_injections.csv` is generated by `scripts/train_synthetic_anomaly_detector.py` for the held-out simulation benchmark. Those rows are known by construction and are not maintenance findings.
